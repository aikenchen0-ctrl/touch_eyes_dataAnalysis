# 轻重触 touch26 数据通道、矛盾与端侧轻量模型分析

日期：2026-10-22

分析范围：单台 OnePlus PHK110 的 29,513 条有效样本，58 个 session，按 session 隔离的五折验证。本文不使用跨设备准确率结论，也不把离线结果直接视为 Android 端性能或全场景准确率。

## 1. 问题重述与 HMM 状态

重述后的问题：

> 在手机端必须保持极低推理开销的约束下，如何从短时触摸与 IMU 数据中稳定识别手指类型和轻重力度，并判断当前 CNN 路线是否仍有更优的轻量替代？

IFR：在不读取隐私内容、不显著增加延迟和耗电的前提下，从自然触摸中可靠获得手指与力度证据。

S0：单一设备、session 与标签强绑定、姿势元数据缺失的数据，主要用多通道 CNN 训练；现有 CNN 制品的严格跨 session 平衡准确率约 66.42%，最差类召回约 11.14%。

Sg：以物理可解释特征和极小分类器为核心，在跨 session、跨姿势、跨设备和真实第三方 App 中保持可用召回，同时让模型权重、乘加量、内存分配和功耗保持在超低预算内。

主要行动者：

- 用户：提供自然触摸，承担误识别和额外延迟。
- 手机触屏与 IMU：提供接触形态、运动与姿态信号。
- 采集者：定义轻、重和手指类型标签。
- 训练与验证流程：决定模型是否真正泛化。
- Android 运行时：决定离线特征能否等价复现，以及推理开销是否可接受。

核心隐藏条件：

- 当前数据没有客观压力参考，轻、重本质上是人的主观动作类别。
- 一个 session 只采一个类别，模型可能学习 session 或采集流程，而不是稳定物理规律。
- 绝对重力主要表示手机姿态，不是触摸力度。
- 触摸面积、半径和比例受设备驱动、用户与采集批次影响，不能直接当作跨设备统一量纲。

## 3. touch26 各通道性质

`sessionVarianceShare` 表示该通道总变化中有多少可由 session 身份解释；`classEffectShare` 表示类别均值差异占总变化的粗略比例。两者只用于发现混杂和冗余，不能单独证明因果作用。

| 通道 | 物理性质 | 可用性与统计 | 主要矛盾 | 建议 |
|---|---|---|---|---|
| x_norm | 触点在屏幕横向的相对位置 | 100% 可用；session 方差 2.2%，类别效应 0.2% | 同时包含手指可达位置和 App 页面布局；作为绝对位置会过拟合屏幕 | 改为相对按下点的位移、边缘距离或速度，降低绝对位置权重 |
| y_norm | 触点在屏幕纵向的相对位置 | 100%；session 方差 2.8%，类别效应 1.7% | 能间接编码拇指/食指可达性，也编码页面布局 | 只保留相对轨迹与上下边缘距离，避免直接使用绝对坐标 |
| userAcceleration.x | 设备坐标系线加速度横向分量 | 100%；session 方差 5.5%，类别效应 1.3% | 既有按压冲击，也混入走路、手抖和翻转 | 用重力坐标系分解、模长、冲击峰和 jerk |
| userAcceleration.y | 线加速度纵向分量 | 100%；session 方差 8.4%，类别效应 3.3% | 信号较强，但随手机姿态旋转 | 与重力坐标系联合变换，保留姿态不变分量 |
| userAcceleration.z | 线加速度垂直分量 | 100%；session 方差 14.2%，类别效应 5.6% | 当前最强的 IMU 单通道之一，但设备方向和握持改变数值 | 保留垂直冲击、水平冲击、幅值和差分，不直接依赖原始 z |
| rotationRate.x | 绕 x 轴角速度 | 100%；session 方差 10.4%，类别效应 3.3% | 手指动作与手机姿态共同改变分量 | 使用模长、jerk 和重力对齐后的分量 |
| rotationRate.y | 绕 y 轴角速度 | 100%；session 方差 10.4%，类别效应 1.2% | 握持方式影响明显 | 作为辅助动态证据，低权重 |
| rotationRate.z | 绕 z 轴角速度 | 100%；session 方差 1.2%，类别效应 0.3% | 受握持影响小，但类别效应也弱 | 保留低权重辅助项 |
| gravity.x | 设备重力方向 x 分量 | 100%；session 方差 47.5%，类别效应 3.2% | 主要编码姿势和 session，容易被误学成类别捷径 | 不进入核心分类特征，只用于坐标系校正 |
| gravity.y | 设备重力方向 y 分量 | 100%；session 方差 81.6%，类别效应 0.08% | 几乎完全由姿势/session 主导，类别信息极弱 | 删除直接特征 |
| gravity.z | 设备重力方向 z 分量 | 100%；session 方差 62.3%，类别效应 0.7% | 与 gravity.y 高度相关，代表手机朝向 | 删除直接特征；仅在变换 IMU 时使用 |
| pressure | 名义接触压力 | 51.3% 有值；有效值恒为 1，标准差 0 | 名称是压力，数据实际只是有效性占位 | 删除数值通道，只保留可用性门控 |
| size | 接触面积或驱动归一化面积 | 51.3%；22 个离散值；session 方差 41.9%，类别效应 17.9% | 类间有信号，但设备与采集批次偏差更大 | 做设备/会话基线校准后使用相对偏差；不单独分类 |
| major_norm | 接触椭圆长轴归一化值 | 51.3%；18 个离散值；session 方差 34.5%，类别效应 16.6% | 与 size 高度相关，量纲还受驱动实现影响 | 与 size 二选一或降维后保留 |
| minor_norm | 接触椭圆短轴归一化值 | 51.3%；22 个离散值；session 方差 54.4%，类别效应 17.3% | 冗余高，跨设备尺度不稳定 | 与 major/size 联合做相对形状，避免三路重复 |
| log_axis_ratio | 长短轴比例的对数 | 51.3%；只有 6 个离散值；session 方差 20.1%，类别效应 11.4% | 姿态信息弱，但分辨率低且与 major 高度相关 | 保留为弱辅助特征，设低权重 |
| orientation_sin | 接触方向正弦 | 0% 可用 | 当前数据完全缺失 | 删除 |
| orientation_cos | 接触方向余弦 | 0% 可用 | 当前数据完全缺失 | 删除 |
| pointer_count | 触点数量 | 51.3% 有值；有效值恒为 1 | 分类信息为零，只能用于拒绝多指 | 不进入网络，作为硬门控 |
| touch_valid | 当前槽是否有真实触摸数据 | 100% 可用；类别效应近 0 | 是观测条件，不是触摸力度 | 只用于掩码、零化和窗口有效性检查 |
| pressure_available | 压力是否可用 | 51.3% | 与 touch_valid 几乎重复 | 只作门控，不送模型 |
| size_available | 面积是否可用 | 51.3% | 与 touch_valid 几乎重复 | 只作门控 |
| major_available | 长轴是否可用 | 51.3% | 与 touch_valid 几乎重复 | 只作门控 |
| minor_available | 短轴是否可用 | 51.3% | 与 touch_valid 几乎重复 | 只作门控 |
| orientation_available | 方向是否可用 | 0% | 恒为零 | 删除 |
| pointer_count_available | 指针数是否可用 | 51.3% | 与 touch_valid 几乎重复 | 只作门控 |

关键冗余：

- size 与 major_norm 的相关系数约为 0.986。
- major_norm 与 log_axis_ratio 约为 0.939。
- size 与 minor_norm 约为 0.930。
- gravity.y 与 gravity.z 约为 -0.870。

把 26 个通道全部送入 CNN 会同时引入大量冗余、缺失掩码和域身份，不是低算力场景下的有效利用方式。

## 4. 按 HMM 做通道矛盾分析

### 4.1 坐标通道

TC：提高绝对坐标权重能提升同设备、同页面下的手指区分，却降低跨页面、跨握持和跨设备泛化。

PC：同一坐标值既要表示手指可达位置，又要表示页面内容位置，两种语义无法由原始坐标区分。

代偿路径：改用相对按下点的位移、速度、路径曲率、距屏幕边缘距离；只在明确的同页面上下文中使用绝对坐标。

### 4.2 线加速度通道

TC：增加三轴原始加速度可提高训练拟合，却同时放大手机方向和身体运动的影响。

PC：同一数值既是触摸力度证据，也是设备姿态和外部运动证据。

代偿路径：以重力方向建立局部坐标，提取垂直冲击、水平冲击、加速度模长、峰值、标准差和 jerk；再用会话基线做相对化。

### 4.3 角速度通道

TC：原始分量越完整，局部动作描述越细；但握持方式越容易成为分类捷径。

PC：角速度既要表达手指/手机响应，又要表达持机动作。

代偿路径：保留旋转模长、重力对齐分量和差分，不把三轴绝对方向作为强特征。

### 4.4 重力通道

TC：绝对重力可帮助拟合采集姿势，却会直接破坏倒置和躺卧泛化。

PC：重力既可用于坐标系校正，又会被模型当作类别身份。

代偿路径：将重力只用于旋转加速度和角速度，不进入分类器；实验已经显示物理 10 通道加重力后，平均 BA 从约 81.05% 降到 75.10%。

### 4.5 pressure、pointer_count、orientation

TC：保留这些字段可以维持 schema 完整性，却增加无信息输入和运行时复杂度。

PC：字段存在是为了表达可用性，但网络会把占位值当作信号。

代偿路径：压力、指针数、方向缺失状态只做硬门控；真实压力不可用时直接不训练该数值通道。

### 4.6 size、major、minor、ratio

TC：接触形态能区分部分轻重样本，却对不同屏幕、驱动和用户标定敏感。

PC：同一面积既要表示按压强度，又受指腹面积、握持角度和设备量程影响。

代偿路径：只保留一个面积代表量和一个形状代表量；用同设备或同会话基线归一化；做缺失感知训练；禁止仅凭形态做四分类。

### 4.7 touch_valid 与各可用性掩码

TC：把掩码送入网络可让模型知道缺失位置，却也会让模型学习采集时序和会话身份。

PC：掩码既要控制特征是否有效，又可能被当作预测特征。

代偿路径：使用确定性零化、掩码统计和样本拒绝规则；不把重复掩码直接作为分类特征。

### 4.8 标签与 session

TC：按单 session 大量采同一类别可提高标注效率，却使 session 与类别高度耦合。

PC：同一 session 既要提供稳定对照条件，又必须包含足够类别变化，才能证明模型学到物理规律。

代偿路径：未来每个 session 交错采集四类；验证同时做 session 隔离、用户隔离和设备隔离；报告最差类召回、最差折和校准误差。

## 5. 当前 CNN 是否是端侧最优

结论：当前 CNN 不是已被证明的端侧最优方案，现有证据反而支持“统计特征加小型 MLP”的候选优于当前 CNN 制品。

必须区分两个 CNN：

| 模型 | 参数 | 五折平均 BA | 最差折 BA | 最差类召回 | 说明 |
|---|---:|---:|---:|---:|---|
| 已导出的 CNN 基线制品 | 约 49,607 | 66.42% | 52.35% | 11.14% | 训练验证 BA 差约 28.45 个百分点 |
| 当前 `StrictTimeGridCnn` 源码 | 约 5,604 | 未找到同架构、同折的独立报告 | 未验证 | 未验证 | 当前源码和既有导出权重架构不一致，不能直接拿旧制品指标替代 |

当前源码 CNN 在 23 通道下约为 5,604 个参数、5,408 MAC。参数量很小并不等于端侧最优：它仍按每帧逐通道卷积，输入、中间张量和归一化层带来额外开销，而且现有同架构严格验证缺失。相反，统计 MLP 把 9 帧先压缩为 60 个物理统计量，后续只做矩阵向量乘，计算路径更短、缓存更小，也更容易实现零分配热路径。

轻量候选结果：

| 模型 | 参数 | 平均 BA | 最差折 BA | 最差类召回 |
|---|---:|---:|---:|---:|
| Stats MLP16 | 1,316 | 80.64% | 75.90% | 56.97% |
| Stats MLP24 多任务 | 2,164 | 82.08% | 79.42% | 66.67% |
| Depthwise CNN16 | 676 | 74.14% | 68.17% | 30.35% |
| Depthwise CNN20 多任务 | 924 | 76.94% | 72.50% | 46.77% |
| Tiny TCN12 | 664 | 71.13% | 61.45% | 17.61% |
| Tiny TCN16 多任务 | 1,012 | 75.76% | 68.80% | 39.10% |

2026-10-22 修复了两处会影响这些数字的训练缺陷：

1. 统计特征曾按“所有通道均值、所有通道标准差……”拼接，而特征名与 Android 端按“通道内五项统计”排列。修复后三处合同使用同一列序，并增加数值级回归测试。
2. 多任务模型的联合概率已经是对数概率，旧训练却再执行一次 softmax。现在主损失直接对联合对数概率计算 NLL，并与两个辅助头共用一次前向和同一 dropout 掩码。

上表来自修复后的固定种子和固定五折。旧报告仅保留为失效审计副本。以下嵌套验证同样使用修复后的列序和联合损失，并以训练折内部的 session 留出决定早停：

| 模型 | 平均 BA | 最差折 BA | 最差类召回 |
|---|---:|---:|---:|
| Stats MLP16 | 79.22% | 75.06% | 52.18% |
| Stats MLP24 多任务 | 80.22% | 76.09% | 60.11% |

特征消融显示：

| 特征组 | 平均 BA | 最差折 BA | 最差类召回 |
|---|---:|---:|---:|
| 物理 10 通道 | 80.97% | 76.99% | 59.45% |
| 物理 10 通道 + 重力 | 76.26% | 71.46% | 45.07% |
| IMU 8 通道 | 69.81% | 62.96% | 39.50% |
| 仅坐标 | 41.76% | 33.90% | 6.49% |
| 仅 size | 24.34% | 20.02% | 0% |
| 仅长短轴比例 | 47.96% | 39.71% | 0.10% |

物理 10 通道为：

`x_norm, y_norm, userAcceleration.xyz, rotationRate.xyz, size, log_axis_ratio`

把它展开为每通道的 mean、std、min、max、首尾差，再增加加速度与角速度的模长、峰值和 jerk，得到 60 个统计特征。Stats MLP24 的 float32 权重约 8.5 KB，int8 理论权重约 2.1 KB。按乘加量估算，它只有数千级 MAC，明显小于多通道卷积链。

但该候选仍不能直接上线：修复后最差类召回为 66.67%，且只有单设备跨 session 证据。相比现有 CNN 的 11.14% 最差类召回，它值得进入下一轮，但还没有达到“全场景可靠”。

## 6. 业界轻量时序模型的可迁移点

- TinierHAR 使用残差深度可分离卷积、GRU 和时间聚合，在多个可穿戴 HAR 数据集上显著降低参数和 MAC。它说明“小通道数、短序列”应优先采用分解卷积和聚合，而非普通大卷积堆叠。其约 34K 参数规模仍大于本场景的 Stats MLP 候选，不能因为论文名为 lightweight 就直接替换。
- TinyHAR 的模块化轻量思路适合更长时序。本项目只有 9 个时间槽，循环网络会引入状态、延迟和运行时复杂度，当前证据不支持优先采用。
- MINIROCKET 使用固定随机卷积核提取特征，再用线性分类器。它的训练和推理都很轻，适合作为下一阶段对照，尤其适合检验是否还存在简单卷积特征能超过统计量 MLP 的收益。
- MobileNets 的深度可分离卷积提供了降低卷积乘加量的通用原则，但它是视觉模型证据，不能直接证明触摸时序上的最优性。
- LiteRT 训练后量化可减小模型和部分设备上的推理开销，但量化必须检查逐样本输出一致性和最差类召回，不能只看文件大小。
- 可穿戴 HAR 研究强调 session、受试者和设备隔离的验证协议。随机样本切分会高估性能，应把 LOSO、留一设备和留一采集批次作为正式门槛。

## 7. 建议的端侧架构

推荐主线：

```text
原始触摸与 IMU
    -> 硬门控：触摸有效、单指、窗口完整
    -> 重力坐标系校正
    -> 10 个物理通道
    -> 9 帧统计与差分特征
    -> 共享 MLP 24
       -> 手指二分类头
       -> 力度二分类头
    -> 组合四类概率
    -> 置信度校准与低置信度拒绝
```

运行策略：

1. 先用一个极小门控模型或规则排除多指、窗口不完整、明显滚动和系统边缘手势。
2. 常规触摸走 Stats MLP16 或 MLP24；高不确定样本再调用更重的 CNN，形成级联，避免每个触摸都运行卷积。
3. 多任务输出分别监督手指和力度，四类概率由两个头的概率组合，降低单一四分类目标对数据不平衡和标签耦合的敏感度。
4. 置信度低时不强行四分类，输出“普通触摸”或等待更多证据。对用户而言，漏触发通常比误触发更安全。
5. 对每台设备保存接触尺寸和 IMU 偏置基线，只上传匿名统计或模型更新，不上传原始触摸轨迹。

建议的运行时实现：

- 推理权重在启动时一次性解析为连续的 `float[]` 或 int8 数组，禁止每次触摸解析 JSON。
- 固定形状、单样本推理，复用输入、隐藏层和输出缓冲区，热路径不分配对象。
- 先测直接 float32 小矩阵乘法和 LiteRT/NNAPI 两条路线；对约 2K 参数模型，通用推理框架的调度开销可能大于计算本身。
- 若 int8 量化导致最差类召回下降超过可接受阈值，就保留 float32；当前模型足够小，未必需要为了压缩权重牺牲校准。
- 特征构建和模型推理放到低优先级专用线程，主线程只发布结果；每次触摸结束时释放中间缓存，避免高频对象保留。

建议的真机验收预算：

| 指标 | 建议门槛 |
|---|---:|
| 权重体积 | 小于 10 KB |
| 常驻工作内存 | 小于 64 KB |
| 特征构建加推理 P50 | 小于 2 ms |
| 特征构建加推理 P95 | 小于 5 ms |
| 热路径堆分配 | 0 次/触摸 |
| 连续运行平均 CPU | 小于单核 0.1% |
| 最差类召回 | 先设 70%，跨设备稳定后再提高 |
| 跨设备最差折 BA | 先设 75%，再按产品风险调整 |

这些是工程目标，不是当前已经达到的结果。

|---|---:|---|

| 交错采集 | 0% | 所有 session 只含一个类别，session 与标签完全绑定 |
| 跨类别 session | 0% | 无法把采集批次和标签效应分离 |
| 姿态留出 | 0 折 | 没有真实躺卧、侧卧、倒置等姿态验证 |

双头实验把手指与力度拆开校准：

| 任务 | 目标覆盖 | 实际覆盖 | 接受准确率 | 最差折 BA | 最差类召回 | 状态 |
|---|---:|---:|---:|---:|---:|---|

| 手指 | 90% | 98.02% | 66.50% | 50.00% | 0% | 不可部署 |

力度头在 70% 目标覆盖时，实际覆盖约 69.8%，接受准确率约 93.2%，但最差类召回仍只有 50%。小米 23127PN0CC 上的手指头尤其不稳定，拇指召回约 15.18%；一加 PHK110 则是指力度的主要弱设备。因此运行时可以保留双头概率供诊断，手指头不得触发高风险动作，力度头也不得在未满足覆盖率和最差类召回门槛时自动触发产品功能。

这项复核也确认了两个容易误读的历史问题：

1. 早期尺寸实验中的列号错误已经失效，旧结果不能用于候选比较；当前从特征名派生源列与物理列，并有回归测试。
2. 旧数据没有逐帧量程元数据，不能把声明量程换算当作已证实的跨设备解。设备 oracle 只用于估计上限，不可部署；重力对齐只部分改善，不能替代姿态数据和坐标系校正。

下一轮采集必须先满足以下协议，再做模型排名：

- 同一 session 内四类交错，每类至少 4 次，记录固定随机或均衡顺序。
- 同时采集坐姿倾斜手持、手持竖直顶朝上、手持竖直顶朝下、仰卧举机、左侧卧、右侧卧；每种姿态独立 session。
- 每条样本写入 `bodyPosture`、`requestedDevicePose`、`grip`、`support`、`taskId` 和 `collectionProtocol=interleaved_v2`。
- 真值只采集明确轻触与明确重触；普通点击不再是当前采集任务或训练准入条件，历史普通点击仅保留为可选诊断数据。
- 训练报告同时输出留一设备、留一姿态、留一 session 和类别平衡 bootstrap；任一接受样本仍出现整类 0 召回时，禁止增加更重模型或导出默认模型。
