# 跨设备时间重采样窗口设计

## 目标

把按下期窗口从“不同设备各取固定帧数”改为“先按真实物理时间建立窗口，再重采样成固定模型输入点”。以 `-3...+5` 为例，模型仍接收 9 个时间槽，但每个槽代表固定的物理时间位置，而不是某台设备的第几个原始传感器回调。

本设计只针对新的跨设备模型契约。已有 `causal_imu11_v1` 和 `causal_imu11_touch9_v1` 保持原行为，旧模型不自动迁移、不自动替换、不自动部署。

## 现状

- schema v6 已保存 IMU 硬件时间、IMU 接收时间、触摸事件时间和触摸接收时间。
- `android/analysis/causal_press_features.py` 当前按 `frameIndex` 取固定原始 IMU 帧，再使用触摸接收时间做 ZOH。
- `AispectCausalPressFeatureBuilder` 已在 Android 端实现同名的 v1 特征契约，但尚未做时间网格重采样。
- 当前 PHK110 数据约 201Hz；跨设备可能出现 120Hz、200Hz、240Hz 和回调抖动，因此同一个 `+5` 原始帧不代表相同的物理时间。

## 设计决定

### 1. 新契约名称

新增两个契约，避免改变旧模型的解释：

- `causal_time_grid_imu11_v2`
- `causal_time_grid_imu11_touch9_v2`

两者的 11 个 IMU 基础通道和可选 9 个触摸通道与 v1 保持一致；改变的是时间轴构造方式，不增加时间戳为模型通道。

### 2. `-3...+5` 的物理含义

默认时间网格固定为 `200Hz`，网格步长 `5ms`：

```text
-15ms, -10ms, -5ms, 0ms, +5ms, +10ms, +15ms, +20ms, +25ms
```

这里的 `0ms` 是 `timeAlignment.downEventElapsedRealtimeNanos` 对应的按下事件时刻。`+5` 表示按下后 25ms 的物理时间位置，而不是第 5 个原始 IMU 帧。

运行时仍然逐帧接收 IMU，但必须等到真实 IMU 硬件时间覆盖 `down + 25ms`，并且为 `+25ms` 网格点提供右侧插值支撑（若没有精确命中，通常需要再等一个真实 IMU 帧），完成质量检查后才组装 9 个重采样点并推理一次。实际延迟因此是 `25ms` 加最多一个有效采样间隔，而不是强行在目标时刻外推。

### 3. IMU 重采样规则

对每个目标时间 `t_grid`：

1. 在 `frames[]` 中按 `sensorTimestampElapsedRealtimeNanos` 排序。
2. 找到 `t_left <= t_grid <= t_right` 的相邻真实 IMU 帧。
3. 对 9 个 IMU 原始连续通道做线性插值：

```text
value(t_grid) = value(left)
  + (value(right) - value(left))
  * (t_grid - t_left) / (t_right - t_left)
```

4. 如果 `t_grid` 恰好命中真实帧，直接使用真实值，不进行浮点插值。
5. 如果缺少左/右帧，或相邻硬件时间间隔超过质量阈值，则该样本窗口无效，不补零、不外推。`+25ms` 端点允许等待第一个硬件时间晚于 `+25ms` 的右支撑帧；该帧只用于插值支撑，不扩大模型的物理目标窗口。

### 4. 触摸 ZOH 规则

触摸字段不能按事件时间或数组下标最近邻匹配。对每个重采样点，使用用于覆盖该时间点的真实 IMU 帧的接收时间作为可用性边界，选择：

```text
最后一个 touchFrame.receivedElapsedRealtimeNanos
<= imuFrame.receivedElapsedRealtimeNanos 的 touchFrame
```

如果目标点位于按下前且没有已接收的触摸帧，使用定义好的无接触占位；按下后缺少可用触摸帧时，窗口直接标记失败，不读取抬起后汇总字段。

### 5. 时间质量阈值

不使用设备声明的名义采样率直接推算时间。对每个样本先计算真实 IMU 硬件时间间隔：

- `median_dt`：窗口覆盖范围内的中位采样间隔。
- `max_gap = max(2 * 5ms, 4 * median_dt)`。
- 任一用于插值的相邻真实帧间隔 `> max_gap`，该样本拒绝进入跨设备时间网格视图。
- 目标网格必须有完整左/右支撑；窗口边界不得使用零填充或线性外推，端点右支撑不足时必须等待真实帧。
- 报告同时记录每个样本的原始采样率、中位间隔、最大间隔、网格覆盖时长和拒绝原因。

### 6. 因果边界

所有重采样目标点均位于 `[-15ms, +25ms]`。模型发布前必须满足：

- 已收到覆盖 `down + 25ms` 且满足端点右支撑的真实 IMU 数据。
- 不使用 `timeSinceAnchor`。
- 不使用根级整次 `contactPatch`、`touchNormalization`、`contactEncoding`。
- 不使用抬起事件、抬起后帧或未来 session 统计。
- 时间戳只用于对齐和质量检查，不作为模型输入通道。

## 数据流

```text
schema v6 原始 JSON
  -> 校验硬件/接收时间
  -> 以 downEventElapsedRealtimeNanos 建立物理时间轴
  -> 提取 -15ms...+25ms 真实 IMU 覆盖
  -> 检查间隔和左右插值支撑
  -> IMU 连续通道线性重采样到 9 个 5ms 网格点
  -> 每个网格点按 IMU 接收时间执行触摸 ZOH
  -> 生成固定 [9, 11] 或 [9, 20] 特征矩阵
  -> 训练/端侧使用同一 featureContract
```

## 需要修改的边界

### Python 离线端

- `android/analysis/causal_press_features.py`：新增 v2 时间网格契约、时间排序、间隔检查、线性插值和 ZOH 对齐。
- `android/analysis/train_android_finger_four_class_cnn.py`：在 scaler、训练报告、缓存签名中写入 `featureContract`、`gridRateHz`、`gridOffsetsMs`、`interpolation` 和 `maxGapRule`。
- 训练 manifest：保留原始样本路径和 SHA-256，新增网格质量字段，不修改原始 JSON。

### Android 端

- `android/aispect-core/src/main/java/com/zhifaios/eyes/aispect/AispectCausalPressFeatureBuilder.java`：新增 v2 入口，保持 v1 入口不变。
- `android/aispect-core/src/main/java/com/zhifaios/eyes/aispect/AispectImpactCNNClassifier.java`：按 scaler 的 `featureContract` 分派 v1 或 v2，不允许凭输入通道数量猜测契约。
- `android/aispect-core/src/main/java/com/zhifaios/eyes/aispect/AispectCollectionController.java`：只有 v2 模型启用时间网格就绪闸门；未覆盖 `+25ms` 或质量检查失败时不发布模型结果。
- `FunctionAndDataStructureDescription.md`：记录 v1/v2 的区别、固定物理网格和拒绝规则。

## 测试设计

### Python 测试

新增 `android/analysis/tests/test_causal_time_grid_features.py`，至少覆盖：

1. 120Hz、200Hz、240Hz 的等价物理信号重采样后得到相同网格值。
2. 不规则采样间隔仍能按硬件时间正确插值。
3. 改变端点右支撑帧之后的未来帧不会改变窗口输出。
4. 修改抬起时间、`timeSinceAnchor`、根级接触汇总不会改变 v2 特征矩阵。
5. 缺少左/右支撑或出现超阈值间隔时稳定拒绝，不补零、不外推。
6. 触摸 ZOH 只按接收时间选择，事件时间更近但尚未收到的触摸帧不能被选择。
7. v1 契约结果保持不变。

### Android 测试

新增 `AispectCausalPressTimeGridFeatureBuilderTest.java`，使用三种采样率和不规则时间戳 fixture，覆盖与 Python 相同的结果、因果、缺帧和超间隔场景。另加 scaler 契约分派测试，确认 v2 不会误走 v1 原始帧索引路径。

### 训练与部署验证

- 使用至少两个设备或两个真实采样率域做严格留出，不能只做同一 PHK110 的随机切分。
- 对比 v1 固定原始帧、v2 时间网格和无触摸通道三个基线。
- 同时报告 balanced accuracy、每类召回、最差域召回、窗口拒绝率和实际等待时长。
- v2 未完成跨设备严格留出和端侧 A/B 前，不替换 Android 默认模型。

## 非目标

- 不修改 schema v6 原始采集字段。
- 不删除历史 v1 模型或旧模型资源。
- 不把时间戳直接加入模型通道。
- 不使用零填充伪造缺失传感器帧。
- 不用名义采样率或数组下标替代硬件时间。
