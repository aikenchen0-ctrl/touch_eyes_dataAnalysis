# Android 原始采集 85ms 双下限设计

## 目标

为 Android schema v6 原始触摸记录增加跨采样率冗余。原始窗口只保存真实 IMU 帧，训练和端侧模型窗口保持独立。

## 采集合同

```text
开始 = min(downIndex - 15, 最晚一个 timestamp <= downEvent - 85ms 的帧)
结束 = max(liftIndex + 15, 最早一个 timestamp >= liftEvent + 85ms 的帧)
```

`windowComplete` 必须同时满足：

- 按下前至少 15 个真实 IMU 帧；
- 按下前实际硬件时间覆盖至少 85ms；
- 抬起后至少 15 个真实 IMU 帧；
- 抬起后实际硬件时间覆盖至少 85ms；
- 选择范围内时间戳连续。

边界采用“前侧向更早、后侧向更晚”的保守取法，不使用最近帧近似覆盖时间，也不补零或外推。

## 收尾等待

抬起后 85ms 首次检查。若按下侧已经完整、抬起侧尚未完整，则每 8ms 轮询一次，最长 500ms。达到超时仍保存真实数据，但 `windowComplete=false`，由清洗层决定是否纳入训练。按下侧缺失无法通过抬起后等待补救，因此不延迟到超时。

## JSON 兼容

根 `schemaVersion` 保持 `6`。新记录增加 `captureWindow` 对象，声明：

- `contract=dual_anchor_min_time_and_frames_v1`；
- 要求的前后时长和帧数；
- 实际前后覆盖时长和帧数；
- 前后时长、前后帧数及合并完成状态。

旧根级计数字段继续写出。缺少 `captureWindow` 的历史 schema v6 文件按旧纯帧数合同识别，不能与新合同无审计混合。

## 模型边界

当前 v2 模型仍按 `-15,-10,-5,0,+5,+10,+15,+20,+25ms` 九个物理时间槽构造输入。扩大原始保存范围不会增加通道、改变训练窗口或改变按下期输出延迟。

## 范围

本次实现覆盖 Android 采集器、Android JSON 审计和 Java 契约测试。iOS 仍使用旧 schema/纯 15 帧采集，后续需单独同构并用真机数据验收后才能合并跨平台原始数据。
