# 原始数据字段剔除评估计划

> **给后续 AI 的执行要求：** 本计划只指导评估和生成派生训练视图，不授权直接删除原始数据。执行时必须先使用独立副本、生成清单和哈希，再由人工确认剔除方案。

**目标：** 建立一套保守、可复现、可审计的原始数据字段剔除评估流程，判断哪些字段可以从训练输入或派生数据视图中剔除，同时保证原始 JSON 始终可回溯、未来特征仍可重建。

**架构：** 原始 schema v6 JSON 只读保存；Python 评估器负责字段盘点、精确重建证明、常量性分析、跨字段相关性和因果泄露审计；评估结果先输出建议，不直接修改源文件。确认后的字段选择通过独立 manifest 和派生训练视图实现，训练输入与原始存档严格分离。

**技术栈：** Python 标准库、现有 Android JSON schema、CSV/JSON 报告、现有 `android/analysis/tests` 测试体系。

---

## 一、当前决策和不可违反的边界

1. 当前不删除任何手机原始 JSON、历史 JSON、模型资源或采集字段。
2. 当前不修改 Android 采集代码；本计划只定义后续评估和清洗流程。
3. 原始文件是证据源，任何删除都必须表现为训练 manifest 或派生目录中的“不使用”，不能先改源文件。
4. “当前设备上恒定”不能直接证明“跨设备恒定”。压力、方向、工具类型、指针数量和工具轴暂时全部保留。
5. “字段可由其他字段重建”必须同时给出重建公式、误差上界、依赖字段和缺失字段时的失败行为。
6. “不进入模型”与“从原始采集删除”是两个不同决定。默认只做前者。
7. 任何包含抬起后信息、整次触摸汇总、未来标签或跨会话统计的字段，只能用于审计或离线诊断，不能进入按下期模型。

## 二、当前数据和 schema 事实

以下数字来自 2026-08-07 从 OnePlus PHK110 导出的 98 条 schema v6 样本，只能作为本轮证据，不能直接推广为所有设备的删除结论：

- 98 条 JSON 全部可解析、均为 schema v6、均为 `accepted`。
- 共 4511 个 IMU 帧、583 个触摸帧，采样率约 201Hz。
- 所有窗口均为真实 `down-15...lift+15`，无补位帧。
- ID 和完整文件哈希均无重复。
- 最近 IMU 帧到按下锚点的最大误差约 2.46ms，到抬起锚点的最大误差约 2.44ms。
- 按下接收时刻之后的 2821 个 IMU 帧全部能够通过接收时间找到可用的触摸帧。
- `frames[].relativeTimestamp` 与 `frames[].timeSinceTouchDown` 在 4511/4511 帧完全相同。
- `frames[].timeSinceAnchor` 在 4511 帧中有 2943 帧为负值；它以抬起参考帧为零点，属于按下期未来信息风险。
- `frames[].x_norm/y_norm` 与按接收时间 ZOH 选择的触摸坐标在 2820/2821 帧完全一致；唯一不一致是一个触摸回调与 IMU 回调并发处理边界，IMU 帧仍保留了 `0,0`。
- 本批次 `pressure`、`orientation`、`toolType`、`pointerCount` 各自只有一个取值；这只能记录为设备内观察，不能作为跨设备删除依据。
- `touchMajor == toolMajor`、`touchMinor == toolMinor` 在本批次 583/583 帧成立；Android 平台语义仍不同，不能只凭本批次直接删除。
- `size` 与 `touchMajor` 的相关系数约 0.987，与 `touchMinor` 的相关系数约 0.935，但不是精确重复。

## 三、当前字段分层

### 3.1 `frames[]` 的直接字段

当前直接字段共 17 个：

| 字段 | 类别 | 初步处理原则 |
|---|---|---|
| `frameIndex` | 结构索引 | 可由数组位置和窗口起点重建，候选剔除 |
| `relativeTimestamp` | 重复相对时间 | 当前与 `timeSinceTouchDown` 完全重复，候选剔除 |
| `x/y/z` | IMU 加速度 | 原始测量，保留 |
| `rotationRateX/Y/Z` | IMU 陀螺仪 | 原始测量，保留 |
| `gravityX/Y/Z` | IMU 重力 | 原始测量，保留 |
| `x_norm/y_norm` | 触摸上下文 | 与 ZOH 触摸帧高度重复，但存在一次并发边界差异；原始存档保留，模型视图单独评估 |
| `timeSinceTouchDown` | 按下相对时间 | 可由 IMU 时间和按下参考帧重建；暂时保留以兼容历史读取，模型默认不使用 |
| `timeSinceAnchor` | 抬起相对时间 | 可重建且含未来信息；原始存档暂时保留，按下期模型强制排除 |
| `sensorTimestampElapsedRealtimeNanos` | IMU 硬件时间 | 对齐和审计必需，保留 |
| `receivedElapsedRealtimeNanos` | IMU 接收时间 | ZOH 因果规则必需，保留 |

### 3.2 `touchFrames[]` 的直接字段

当前直接字段共 18 个：

| 字段 | 类别 | 初步处理原则 |
|---|---|---|
| `frameIndex` | 结构索引 | 可由数组位置重建，候选剔除 |
| `relativeTimestamp` | 触摸相对时间 | 可由事件时间和按下锚点重建，但保留原始值用于审计 |
| `eventTimeMillis` | Android 原始事件时间 | 原始来源证据，保留 |
| `eventElapsedRealtimeNanos` | 统一事件时间 | 对齐必需，保留 |
| `receivedElapsedRealtimeNanos` | 触摸接收时间 | ZOH 因果规则必需，保留 |
| `x/y` | 原始屏幕坐标 | 原始测量，保留 |
| `x_norm/y_norm` | 屏幕归一化坐标 | 跨设备候选输入，保留 |
| `pressure` | 压力 | 当前设备恒定，但跨设备未知，保留 |
| `size` | 系统归一化面积 | 与接触轴相关但不等价，保留 |
| `touchMajor/touchMinor` | 接触椭圆轴 | 原始触摸测量，保留 |
| `toolMajor/toolMinor` | 工具轴 | 当前与触摸轴相同，但平台语义不同，保留 |
| `orientation` | 接触方向 | 当前恒定，跨设备可能变化，保留 |
| `toolType` | 工具类型 | 当前为手指，未来可能有触控笔，保留 |
| `pointerCount` | 指针数量 | 当前为单指，未来多指场景需要，保留 |

### 3.3 嵌套字段和根级字段

- `touchFrames[].axisAvailability`：字段能力标记，不是物理通道；原始存档保留，模型输入单独评估。
- `touchFrames[].contactPatch`：逐触摸帧派生结果，不能与根级整次触摸汇总混淆。
- 根级 `contactPatch`、`touchNormalization`、`contactEncoding`：含整次触摸或会话统计的派生结果，原始存档暂时保留，按下期模型禁止直接读取。
- 根级 `anchorTimestamp`、`referenceFrameIndex`、`endFrameIndex`、`preDownFrameCount`、`postLiftFrameCount`、`motionSignal.frameCount`、`motionSignal.sampleRateHz`：部分是可重建或重复摘要，未来 schema 版本可评估剔除，但当前为兼容旧工具暂时保留。
- `touchEvents[]`：包含交互语义、结束类型和偏移信息，不能只用 `touchFrames[]` 直接替代，暂时保留。

## 四、后续评估的判定等级

评估器必须给每个字段输出以下等级之一，不允许只输出“删/不删”二元结论：

| 等级 | 含义 | 处理方式 |
|---|---|---|
| A：绝对结构冗余 | 由数组位置或同一记录中的字段精确重建，误差为 0 | 可在派生训练视图剔除；源 JSON 仍保留，除非人工批准 schema 升级 |
| B：严格派生字段 | 可由原始时间或参考帧重建，有明确误差上界 | 默认只从模型输入剔除；记录重建公式和误差 |
| C：设备内常量或高度相关 | 只在当前设备/当前批次成立 | 不从原始采集删除，只作为消融候选 |
| D：因果风险字段 | 含抬起、未来、整次触摸结束后或会话未来信息 | 原始存档保留，按下期训练强制排除 |
| E：原始测量字段 | 无可靠无损重建证据，或未来设备可能变化 | 保留 |
| F：语义/审计字段 | 不一定进入模型，但用于追责、复现、能力分析 | 保留，禁止未经确认删除 |

任何字段只有在满足以下全部条件后，才可以进入 A 或 B：

1. 给出字段级重建公式。
2. 在所有可用样本上逐值比较。
3. 报告最大绝对误差、相对误差、失败样本数和失败原因。
4. 证明重建不依赖决策帧之后的信息，或明确标记为仅可用于非因果离线视图。
5. 证明重建所需的参考字段本身不会在同一轮剔除中被删除。

## 六、给未来 AI 的完整提示词

下面的提示词可直接复制给未来负责原始字段评估的 AI。未来 AI 必须先阅读本计划，再读取实际输入目录；不能只依据当前 98 条样本的统计结果做删除决定。

```text
你负责评估 Android schema v6 原始触摸/IMU 数据中哪些字段可以从训练输入或派生视图剔除。

你的任务不是删除原始数据，而是生成可审计的字段评估报告和派生训练视图建议。原始 JSON 必须只读；任何源文件删除、重命名、覆盖或字段改写都禁止。开始前先记录输入目录绝对路径、文件数、每个文件 SHA-256、schema 版本、设备、采集者和 session 数量。

一、当前数据结构

1. frames[] 是 IMU 序列。字段包括：
   frameIndex, relativeTimestamp, x, y, z, x_norm, y_norm,
   rotationRateX, rotationRateY, rotationRateZ,
   gravityX, gravityY, gravityZ,
   timeSinceTouchDown, timeSinceAnchor,
   sensorTimestampElapsedRealtimeNanos, receivedElapsedRealtimeNanos。

2. touchFrames[] 是触摸事件序列。字段包括：
   frameIndex, relativeTimestamp, eventTimeMillis,
   eventElapsedRealtimeNanos, receivedElapsedRealtimeNanos,
   x, y, x_norm, y_norm, pressure, size,
   touchMajor, touchMinor, toolMajor, toolMinor,
   orientation, toolType, pointerCount。

3. touchFrames[] 还可能有 axisAvailability 和逐帧 contactPatch；根级也可能有 contactPatch、touchNormalization、contactEncoding。必须区分逐帧数据和整次触摸结束后的汇总数据。

4. timeAlignment 包含：
   clock,
   downEventElapsedRealtimeNanos,
   downReceivedElapsedRealtimeNanos,
   liftEventElapsedRealtimeNanos,
   liftReceivedElapsedRealtimeNanos,
   availabilityRule。

二、绝对规则

1. 原始 JSON 只读，禁止直接删除字段。
2. “当前设备恒定”不能证明“跨设备恒定”，不能据此自动删除 pressure、orientation、toolType、pointerCount、toolMajor、toolMinor 等字段。
3. 只有在给出精确重建公式、逐值验证、最大误差和失败样本后，才能把字段标为“结构冗余”或“严格派生”。
4. 相关系数只能产生消融候选，不能证明信息包含关系。
5. 训练按下期只能使用决策时刻已经可用的数据。
6. 对每个 IMU 帧，触摸帧选择规则必须是：
   选择最后一个满足
   touchFrames[j].receivedElapsedRealtimeNanos <= frames[i].receivedElapsedRealtimeNanos
   的触摸帧。禁止按数组下标、名义采样率或最近事件时间替代。
7. timeSinceAnchor 是抬起相对字段，默认判为因果风险字段；根级整次触摸汇总默认判为因果风险字段。
8. 未经人工批准不得生成“删除源文件”的动作，只能生成派生 manifest 或派生目录。

三、逐字段评估方法

对每个字段输出：
field_path、字段类别、数据类型、出现率、唯一值数、缺失率、分组常量性、精确重建公式、最大绝对误差、最大相对误差、失败样本、未来信息风险、跨设备风险、建议等级、建议动作、依赖字段。

建议等级只能使用：
A 绝对结构冗余：数组位置或同记录字段可零误差重建；
B 严格派生字段：有公式和明确误差上界；
C 设备内常量或高度相关：只能做消融候选，不能自动删除；
D 因果风险字段：保留原始值，但按下期模型禁止使用；
E 原始测量字段：保留；
F 语义/审计字段：保留，除非人工确认。

四、必须检查的关系

1. frames.relativeTimestamp 是否逐值等于 timeSinceTouchDown。
2. frameIndex 是否可由数组位置和 startFrameIndex 重建。
3. timeSinceTouchDown 是否可由 IMU 硬件时间和按下参考帧重建。
4. timeSinceAnchor 是否可由 IMU 硬件时间和抬起参考帧重建；即使可重建，也必须标为 D，不能用于按下期训练。
5. 触摸 relativeTimestamp 是否可由事件时间和按下事件时间重建，并报告毫秒误差。
6. frames.x_norm/y_norm 与 ZOH 触摸坐标是否逐帧相等；任何一次不等都要单独报告，不能按多数投票宣布等价。
7. touchMajor/toolMajor、touchMinor/toolMinor 是否精确相等；即使当前相等，也要标记 Android 语义差异和跨设备风险。
8. pressure、orientation、toolType、pointerCount 是否在设备组、session 组和全局都恒定。
9. size 与接触长短轴的相关性只能作为消融证据，不能作为删除证据。
10. x/y 与 x_norm/y_norm 是否有屏幕尺寸证据；没有尺寸时不得声称可互相重建。
11. 根级摘要字段是否与 frames 长度、窗口索引或其他根字段重复。
```
