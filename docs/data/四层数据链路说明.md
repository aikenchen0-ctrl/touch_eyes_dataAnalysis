<四层数据链路说明>

<文档目标>

说明按下期四分类模型从“采集端原始数据”到“逐时间戳归一化数据”、再到“训练端清洗后数据”和“运行端模型输入”的完整链路。

本文重点回答：每层有什么数据、做了什么处理、哪些进入训练、哪些只保留观察、哪些存在跨设备参考系差异、哪些存在跨设备量纲或归一化差异。

</文档目标>

<核心结论>

1. schema v6 采集文件同时保存原始证据和派生快照，但两者权级不同。
2. `frames[]`、`touchFrames[]`、双时钟和设备元数据是可追溯依据；派生值必须能从这些数据重算。
3. 采集时只有物理预处理和简单几何归一化，没有训练 scaler，也没有固定时间网格重采样。
4. 抬起后生成的整次触摸汇总包含决策时刻之后的信息，只留作观察，禁止进入按下期模型。
5. 跨设备单位、轴、屏幕方向和采样率在第二层统一；训练集统计缩放在第三层完成，二者不能混称为同一种归一化。
6. 运行端不是每来一帧就调用一次 CNN，而是持续缓存，等到 `+25ms` 有完整支撑后，一次性输入 `9×通道数` 矩阵。

</核心结论>

<数据用途定义>

| 用途 | 定义 |
|---|---|
| 正式训练输入 | 已证明在决策时刻可获得，并有训练端与运行端同构实现的数据 |
| 条件训练输入 | 可进入实验，但跨设备一致性或字段覆盖率仍需验证的数据 |
| 仅观察 | 原始文件继续保存，用于设备分析、消融、质量诊断，当前不进入模型 |
| 治理字段 | 用于去重、切分、追踪和统计，不作为模型数值通道 |
| 禁止训练 | 会泄露未来、标签、session 或设备身份的数据 |

</数据用途定义>

<归一化术语定义>

| 名称 | 所在阶段 | 含义 |
|---|---|---|
| 物理预处理 | 采集层 | 含重力加速度减去重力，得到线性加速度；不是统计归一化 |
| 即时几何归一化 | 采集层 | 坐标除以视图宽高，得到 `x_norm/y_norm` |
| 单位与参考系统一 | 逐时间戳归一化层 | 统一加速度、陀螺仪单位，并把 Android、iOS 轴映射到统一机身坐标 |
| 时间重采样 | 逐时间戳归一化层 | 按真实时间生成固定九槽网格，不按数组帧序号取样 |
| 触摸几何归一化 | 逐时间戳归一化层 | 半径除以视图对角线、坐标旋转到标准屏幕方向、方向转为正弦余弦 |
| 缺失编码 | 逐时间戳归一化层和清洗层 | 缺失值用数值占位，并用独立 availability 通道说明是否真实可用 |
| 统计标准化 | 训练层 | 仅用训练分区拟合中位数和四分位距，再截断到 `[-8,8]` |

</归一化术语定义>

<第1层_采集端原始数据>

<层级目的>

尽可能完整地保存一次触摸的事实，使未来可以更换窗口、通道、归一化方式和模型，而无需重新猜测原始事件。

</层级目的>

<记录级数据>

| 数据组 | 代表字段 | 采集时处理 | 当前用途 | 跨设备风险 |
|---|---|---|---|---|
| 样本身份 | `id`、`createdAt`、`schemaVersion`、`platform` | 原样记录 | 治理字段 | 平台和版本格式不同，不能进入模型 |
| 人工标签 | `fingerType`、`touchStrength`、`motionState` | 用户选择后锁定 | 训练真值和分层统计 | 标签习惯可能因采集者变化，需要采集规范 |
| 采集身份 | `collector.userName`、`collector.deviceId` | 原样记录 | 治理字段 | 与类别绑定时会形成 session 污染，禁止进入模型 |
| 会话身份 | `collectionSessionID`、`collectionSessionStartedAt` | 原样记录 | 分组切分和去重 | session 与标签绑定会高估验证分数 |
| 双锚点 | 按下、抬起时间与参考帧索引 | 以按下为主轴定位 | 窗口重建和质量检查 | 不同时间源必须统一到单调时钟 |
| 原始窗口质量 | `captureWindow`、`preDownFrameCount`、`postLiftFrameCount`、`windowComplete`、`sampleRateHz` | 采集结束后按真实时间戳和真实帧数统计 | 仅观察和筛选 | 名义采样率不能用于跨设备直接取帧 |
| 设备能力 | `deviceCapability`、`motionSignal` | 采集结束后汇总 | 仅观察和设备分层 | 设备型号和传感器能力不可作为类别捷径 |

</记录级数据>

<每个惯性测量帧数据>

`frames[]` 当前落盘 17 个字段。

| 数据组 | 字段 | 采集层处理 | 当前训练状态 | 跨设备问题 |
|---|---|---|---|---|
| 线性加速度 | `x/y/z` | 优先读取 `TYPE_LINEAR_ACCELERATION`；回退时要求重力时间差不超过 50ms，再计算加速度减重力 | 正式训练输入 | Android、iOS 来源、单位、轴符号可能不同 |
| 陀螺仪 | `rotationRateX/Y/Z` | 原值记录，Android 单位声明为 `rad/s` | 正式训练输入 | iOS 与 Android 轴方向可能不同，部分来源可能使用度每秒 |
| 重力 | `gravityX/Y/Z` | 原值记录在设备机身轴中 | 条件训练输入 | 强烈包含握持姿态；跨平台轴、符号和传感器实现不同 |
| 触摸位置快照 | `x_norm/y_norm` | 最近触摸坐标除以宽高并截断到 `[0,1]` | 仅观察 | 正式矩阵从 `touchFrames[]` 重新对齐，不直接用该快照 |
| 相对时间 | `relativeTimestamp`、`timeSinceTouchDown`、`timeSinceAnchor` | 便于原始审计 | 禁止训练 | 会暴露锚点或剩余按压时长，可能形成未来泄露 |
| 帧索引 | `frameIndex` | 双锚点窗口中的相对位置 | 治理字段 | 不同设备采样率下相同索引不代表相同物理时间 |
| 双时钟 | 硬件时间、接收时间 | 原样记录 | 治理字段 | 用来对齐，不能直接输入模型 |

`delta` 和 `maxAbsDelta` 不属于 schema v6 落盘字段；需要时只能在派生阶段由相邻时间槽重新计算。

</每个惯性测量帧数据>

<每个触摸帧数据>

| 数据组 | 字段 | 采集层处理 | 当前训练状态 | 跨设备问题 |
|---|---|---|---|---|
| 原始坐标 | `x/y`、视图宽高 | 像素原值记录 | 经第二层归一化后训练 | Android 像素、iOS point、屏幕旋转和分辨率不同 |
| 即时坐标归一化 | `x_norm/y_norm` | 坐标除以视图宽高并截断 | 正式训练输入 | 仍需在第二层按屏幕旋转矩阵转换 |
| 压力 | `pressure` | 系统值原样记录 | 条件训练输入 | OEM 和平台量程、灵敏度、缺失语义不同；不能假设同一数值代表同一物理压力 |
| 接触面积代理 | `size` | 系统值原样记录 | 条件训练输入 | Android `size` 通常是设备定义的归一化代理，不是统一物理面积 |
| 触摸长短轴 | `touchMajor/touchMinor` | 像素原值记录 | 经第二层归一化后条件训练 | 像素密度、触控固件、字段是否存在均不同 |
| 工具长短轴 | `toolMajor/toolMinor` | 原值记录 | 仅观察 | 设备覆盖率和语义不稳定，当前不进模型 |
| 触摸方向 | `orientation` | 弧度原值记录 | 仅观察，当前 `touch23` 已移除 | 可用范围和零方向跨设备不稳定，很多样本缺失 |
| 工具类型 | `toolType` | 原值记录 | 仅观察 | 平台枚举不同，当前任务只保留手指数据 |
| 指针数 | `pointerCount` | 原值记录 | 单指筛选和条件训练 | 多指样本当前剔除，不能把缺失误当单指 |
| 轴可用性 | `axisAvailability` | 逐字段记录系统是否支持 | 正式缺失掩码来源 | 不同设备支持集合不同，是跨设备处理的必要信息 |
| 双时钟 | 事件时间、接收时间 | 原样记录 | 对齐字段 | 决定触摸帧在目标 IMU 时刻是否已经可用 |
| 单帧接触派生 | 每帧 `contactPatch` | 由该触摸帧即时计算 | 仅观察 | 当前正式 v2 白名单不读取该对象 |

</每个触摸帧数据>

<采集时实时处理>

1. 持续缓存真实 IMU 回调。
2. 将含重力加速度转换为线性加速度；这属于物理预处理。
3. 将当前触摸坐标除以视图宽高得到 `x_norm/y_norm`；这属于即时几何归一化。
4. Android SensorEvent 当前已处于设备机身坐标，因此写入单位轴矩阵；不旋转到地球参考系。
5. 不做中位数、均值方差、设备分位数、session baseline 或模型 scaler。
6. 不在采集时强制压缩为九槽训练矩阵，原始可变长度序列继续保留。

</采集时实时处理>

<触摸结束时处理>

| 结束时产物 | 数据来源 | 保留原因 | 训练状态 |
|---|---|---|---|
| 双锚点可变窗口 | Android 从 `down-85ms` 与前 15 帧中更早者，记录到 `lift+85ms` 与后 15 帧中更晚者 | 同时覆盖高、低采样率并为未来窗口调整保留冗余 | 原始证据，不直接作为固定模型矩阵 |
| 根级 `contactPatch` | 整次 `touchFrames[]` 聚合 | 观察接触形态和字段质量 | 禁止进入按下期模型 |
| `contactEncoding` | 整次触摸的高斯、协方差或多通道编码 | 历史消融和未来研究 | 禁止进入按下期模型 |
| `touchNormalization` | screen scale、covariance matrix、session baseline 三方案 | 对比不同触摸归一化方法 | 禁止进入按下期模型 |
| `motionSignal`、能力摘要 | 整次采集状态 | 质量诊断和设备分层 | 仅观察 |
| `cnnPrediction` | 当时模型输出 | 复现诊断 | 禁止作为训练标签或特征 |

这些对象在抬起后才完整，因此可能包含决策时刻之后的数据。保留它们是为了观察和重建，不代表训练白名单允许读取。

</触摸结束时处理>

<采集层输出>

每次触摸输出一个 schema v6 JSON。文件中同时存在：

- 原始证据：原始字段、双时钟、设备元数据、字段可用性和可变长度序列。
- 窗口审计：`captureWindow.contract=dual_anchor_min_time_and_frames_v1`，以及前后要求/实际时长、要求/实际帧数和分项完成状态。
- 可安全重算的逐帧派生值：如 `x_norm/y_norm`。
- 观察性整次汇总：如 `touchNormalization` 和根级 `contactPatch`。

后续层必须采用字段白名单，不能因为字段存在就全部送入训练。

</采集层输出>

</第1层_采集端原始数据>

<第2层_逐时间戳归一化数据>

<层级目的>

把不同平台、采样率、单位、设备轴和屏幕方向的数据，转换成同一物理时间与机身参考系下的因果矩阵。

</层级目的>

<跨设备参考系统一>

| 数据 | 风险 | 统一规则 | 当前状态 |
|---|---|---|---|
| 加速度 | Android 可能是线性加速度或含重力加速度；iOS 常为 userAcceleration | 统一为 `m/s²`，必要时减重力 | Android 已实现；iOS 必须提供有效元数据 |
| 陀螺仪 | 可能使用 `rad/s` 或 `deg/s`，轴符号不同 | 统一为 `rad/s`，再乘显式三轴变换矩阵 | 离线适配器已实现 |
| 重力 | 轴方向不同且包含绝对握持姿态 | 转到 canonical device 机身坐标；不转到地球坐标 | 绝对值、删除和差分三种方式继续 A/B |
| 触摸坐标 | Android 像素、iOS point，横竖屏方向不同 | 先除以视图尺寸，再用二维坐标变换矩阵转到标准屏幕方向 | Android 元数据已实现 |
| 触摸半径 | pixels、points、millimeters 量纲不同 | 读取单位和视图尺寸，当前除以视图对角线 | 已实现，但不是完全物理等价 |

统一机身参考系定义为：`x=device_right`、`y=device_up`、`z=device_outward`。轴变换矩阵必须正交，且行列式绝对值为 1；禁止根据样本数值猜测平台轴。

</跨设备参考系统一>

<跨设备归一化差异>

| 数据 | 当前方法 | 尚存问题 | 处理原则 |
|---|---|---|---|
| `x/y` | 除以视图宽高 | 刘海、安全区和触摸区域定义仍可能不同 | 保留原始坐标和视图尺寸 |
| `touchMajor/touchMinor` | 除以视图对角线 | 相同归一化值不一定对应相同毫米尺寸，DPI 和固件仍会影响 | 当前条件训练；未来可对比毫米或设备校准方案 |
| `pressure` | 截断到 `[0,1]` 并附 availability | 平台与 OEM 的压力曲线不统一 | 不覆盖原值；做跨设备消融和分布审计 |
| `size` | 截断到 `[0,1]` 并附 availability | 不是统一物理面积 | 条件训练，不单独作为重触充分条件 |
| `orientation` | 转为 sin/cos | 零方向和可用性不稳定 | 原始保留，当前正式 `touch23` 移除 |
| session baseline | 采集文件保留历史方案 | 依赖先验样本，可能引入 session 和设备身份 | 当前只观察，不进入正式因果矩阵 |
| covariance/contact patch | 采集文件保留历史方案 | 整次聚合会读取未来触摸帧 | 禁止进入按下期矩阵 |

</跨设备归一化差异>

<物理时间重采样>

1. 以 `ACTION_DOWN` 事件时间为 `0ms`。
2. 固定九个时间槽：`-15,-10,-5,0,+5,+10,+15,+20,+25ms`。
3. 加速度、陀螺仪和重力按硬件时间做左右帧线性插值。
4. 左右支撑必须存在，间隔上限为 `max(10ms, 4×窗口中位采样间隔)`；不外推、不补伪帧。
5. 抬起早于 `+25ms` 的样本不满足当前窗口。
6. 触摸使用零阶保持：选择在目标 IMU 时刻前已经发生且已经被 App 收到的最后一个 `touchFrame`。

</物理时间重采样>

<逐帧触摸规范化>

1. 坐标转为标准屏幕方向后的 `x_norm/y_norm`。
2. 长短轴除以视图对角线，生成 `major_norm/minor_norm`。
3. 生成 `log_axis_ratio`。
4. 方向生成 `orientation_sin/orientation_cos`。
5. 缺失测量写数值 0，同时生成独立 availability；0 不能被解释为真实的小压力或小半径。

</逐帧触摸规范化>

<第3层_训练端清洗后数据>

<数据清洗>

| 操作 | 规则 | 目的 |
|---|---|---|
| 来源一致性 | accepted source、`9×11` 和 `9×20` 必须按 SHA-256 一一对应 | 防止矩阵错配和重复来源 |
| 形状与数值检查 | 固定九槽、通道数正确、全部有限值、掩码为 0 或 1 | 阻止损坏数据进入训练 |
| 标签检查 | 只允许四个目标类别 | 防止未知标签污染 |
| 分组身份检查 | 必须有 platform、deviceId、sessionId | 支持无 session 泄露切分 |
| 多指筛选 | 当前单指模型排除 pointerCount 大于 1 | 保持任务定义一致 |
| 完全重复处理 | 同组同类且矩阵完全相同的样本权重设为 `1/重复数` | 不让重复回调放大样本贡献 |
| 分组切分 | `groupId=platform+deviceId+sessionId`，整组进入训练或验证 | 避免同一 session 同时出现于两侧 |

</数据清洗>

| pointer_count、touch_valid | 2 | 正式状态信息 | 缺失与真实 0 必须区分 |

</当前23通道用途归纳>

<仅采集暂不训练的数据>

| 数据 | 保留原因 | 暂不训练原因 |
|---|---|---|
| `toolMajor/toolMinor`、`toolType` | 未来工具类型和设备能力研究 | 覆盖率和跨平台语义不稳定 |
| 原始 `orientation` | 未来重新定义方向参考系 | 当前设备覆盖不足且零方向不统一 |
| 单帧和根级 `contactPatch` | 接触形态研究 | 正式白名单尚未证明其增益，根级还存在未来泄露 |
| `contactEncoding` | 高斯、协方差、多通道消融复现 | 整次触摸汇总，不满足按下期因果性 |
| `touchNormalization` 三方案 | 比较设备归一化策略 | 依赖整次触摸或 session baseline |
| `deviceCapability`、`motionSignal`、sampleRate | 质量分层和设备审计 | 容易成为设备或 session 捷径 |
| 原始时间戳和相对时间 | 重采样与追溯 | 直接输入会暴露锚点和按压时长 |
| collector、session、deviceId、文件名时间 | 去重、切分、追溯 | 明确属于身份污染 |
| 抬起时间、liftOffset、sourceTouchKind | 标签和交互审计 | 决策时刻不可获得或与标签强绑定 |
| 历史 `cnnPrediction` | 模型复现 | 不能作为真值或输入特征 |

</仅采集暂不训练的数据>

<统计标准化>

1. 严格评估时，scaler 只读取训练分区。
2. 连续通道使用中位数和四分位距进行 robust scaling，并截断到 `[-8,8]`。
3. `x_norm/y_norm`、`touch_valid` 和 availability 保持 identity。
4. 某触摸测量不可用时，该帧不参与该通道 scaler 拟合，转换结果由掩码控制为 0。
5. session、设备和验证集不得影响 scaler。

</统计标准化>

<第4层_运行端模型装机数据>

<在线处理顺序>

1. App 持续预热 IMU 滚动缓存。
2. `ACTION_DOWN` 建立 0ms 锚点，并持续记录触摸双时钟。
3. 每个回调先进入缓存，不单独调用 CNN。
4. 等待 IMU 硬件时间覆盖 `+25ms` 且具备右侧插值支撑。
5. 按模型 `featureContract` 在线执行与第二层相同的单位、机身轴、九槽插值、触摸零阶保持和缺失掩码。
6. 使用导出的 scaler 执行与第三层相同的逐通道转换。
7. 将完整 `9×20` 或 `9×23` 矩阵一次性送入 CNN，输出四类概率、分类结果、置信度和 modelId。

</在线处理顺序>

<运行端禁止项>

- 不读取根级 `contactPatch`、`contactEncoding` 或 `touchNormalization`。
- 不读取抬起后的触摸帧或汇总结果。
- 不读取 session、collector、deviceId、文件名或人工标签。
- 不将时间戳、`timeSinceTouchDown` 或 `timeSinceAnchor` 作为模型通道。
- 合同、通道顺序、矩阵形状、网格、scaler 或权重不一致时拒绝加载或预测。

</运行端禁止项>

<当前未完成事项>

1. Android schema v6、Android `85ms + 15帧` 原始冗余、离线 v2 和 Android 在线时间网格已实现。
2. iOS 必须补齐同等级的 schema v6 双时钟、单位、显式轴变换元数据和 `85ms + 15帧` 原始窗口，并用真机数据验收后才能与 Android 合并训练。
3. 视图对角线只能部分解决触摸半径的跨设备量纲问题，仍需通过未见设备留出比较毫米归一化、分位数校准或删除半径的效果。
4. pressure 和 size 的跨 OEM 数值可比性尚未证明，必须做设备分布审计和通道消融。
5. availability 可能间接编码设备能力，必须在未见设备验证中检查是否成为设备捷径。
6. 全量 A/B 模型没有独立验证集，不能替代严格分组和跨设备验证。

</当前未完成事项>

<验收标准>

1. 同一物理信号在不同采样率和不规则采样下生成误差范围内一致的九槽矩阵。
2. Android 和 iOS 经显式单位与轴变换后落入同一 canonical device 机身参考系。
3. 修改 `+25ms` 之后的数据、抬起后汇总、session 或设备身份不会改变模型输入。
4. 同一 group 不跨训练和验证，验证集不参与 scaler 拟合。
5. Python 与 Android 对同一样本生成的矩阵逐元素一致。
6. 每个条件训练通道都完成跨设备缺失率、分布漂移和消融收益审计。
7. 报告必须包含 balanced accuracy、macro F1、四类召回、最差 session、最差设备、拒绝率和实际等待延迟。
8. Android 新原始样本必须声明版本化 `captureWindow` 合同；完整样本的按下前和抬起后覆盖必须各自同时不少于 `85ms` 与 `15` 个真实 IMU 帧，且原始窗口扩大不得改变九槽模型矩阵。

</验收标准>
