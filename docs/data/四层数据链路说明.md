# 四层数据链路说明

## 1. 文档目的

本文定义按下期四分类 CNN 从采集到装机推理的唯一数据链路：

```text
采集端原始数据
  -> 逐时间戳归一化数据
  -> 训练端使用的清洗后数据
  -> 运行端模型装机输入数据
```

目标类别为 `thumb_light`、`thumb_heavy`、`index_light`、`index_heavy`。当前跨设备时间窗口以 `ACTION_DOWN=0ms`，固定取：

```text
-15, -10, -5, 0, +5, +10, +15, +20, +25ms
```

四层的核心边界如下：

| 层 | 主要职责 | 明确不做 |
| --- | --- | --- |
| 采集端原始数据 | 完整保存可追溯事实、双时钟、来源和冗余窗口 | 不做训练 scaler，不压成九槽，不决定最终通道 |
| 逐时间戳归一化数据 | 统一时间、单位、参考系、触摸量纲和缺失语义 | 不做数据集切分，不使用验证集统计量 |
| 训练端清洗后数据 | 去重、筛选、分组、选通道、拟合 scaler、训练与评估 | 不读取未来汇总或身份字段作为特征 |
| 运行端模型输入数据 | 在线复现第二、三层的全部确定性变换并推理 | 不按单帧反复调用 CNN，不重新拟合 scaler |

## 2. 数据性质和训练权限

schema v6 JSON 是原始记录容器，不等于“每个字段都是原始传感器值”。一个文件同时包含原始测量、逐帧轻量派生值、治理元数据和抬起后整次汇总。

| 权限 | 定义 | 典型数据 |
| --- | --- | --- |
| 正式训练 | 决策时刻可获得，且训练端和运行端已有同构实现 | 统一后的线性加速度、陀螺仪、坐标、状态掩码 |
| 条件训练 | 因果上可用，但跨设备量纲、覆盖率或姿态影响尚需验证 | 绝对重力、pressure、size、touchMajor、touchMinor |
| 仅采集观察 | 保留原始证据，当前不进入正式模型 | rotation vector、toolMajor、toolMinor、原始 orientation |
| 治理字段 | 用于去重、切分、审计、拒绝和追溯 | SHA-256、session、collector、deviceId、时间戳、来源版本 |
| 禁止训练 | 会泄露标签、未来、会话或设备身份 | 人工标签、抬起时间、整次汇总、文件名时间、历史预测 |

后续所有派生脚本和运行端都必须使用显式字段白名单。字段“已采集”不代表“允许训练”。

## 3. 第一层：采集端原始数据

### 3.1 本层目的

采集层保存一次触摸的可重建事实，使后续可以改变时间窗口、通道组合和归一化算法，而不必从帧率或汇总结果反推原始事件。

### 3.2 记录级数据

| 数据组 | 代表字段或对象 | 用途 | 训练权限 |
| --- | --- | --- | --- |
| 样本身份 | `id`、`createdAt`、`schemaVersion`、`platform` | 版本与追溯 | 治理 |
| 人工真值 | `fingerType`、`touchStrength`、`motionState` | 生成四分类标签和分层统计 | 只作标签，不作通道 |
| 采集身份 | `collector.userName`、`collector.deviceId` | 来源审计 | 禁止作通道 |
| 会话身份 | `collectionSessionID`、会话开始时间 | 分组切分、防 session 泄露 | 禁止作通道 |
| 对齐锚点 | 按下、抬起的事件时间和接收时间 | 建立 0ms、判断因果可用性 | 治理 |
| 原始窗口合同 | `captureWindow`、前后时长/帧数、参考帧索引、`windowComplete` | 验证原始冗余是否完整 | 治理和筛选 |
| 传感器元数据 | `sensorMetadata` | 声明单位、来源、轴和变换版本 | 治理和适配 |
| 触摸元数据 | `touchMetadata` | 声明视图、旋转、量纲和字段能力 | 治理和适配 |
| 设备能力摘要 | `deviceCapability`、`motionSignal` | 设备分层、质量诊断 | 仅观察 |
| 整次触摸汇总 | 根级 `contactPatch`、`contactEncoding`、`touchNormalization` | 历史复现和研究 | 按下期模型禁止训练 |
| 历史模型输出 | `cnnPrediction` | 线上复现和回归诊断 | 禁止作标签或通道 |

### 3.3 `frames[]`：每个 IMU 帧的 20 个落盘字段

当前序列化结果是 20 个字段，不是 17 个。代码中的 `RAW_FRAME_FIELDS` 是兼容/白名单集合，不能代表完整 JSON schema。

| 分组 | 数量 | 字段 | 含义和权限 |
| --- | ---: | --- | --- |
| 索引与相对时间 | 4 | `frameIndex`、`relativeTimestamp`、`timeSinceTouchDown`、`timeSinceAnchor` | 只用于审计和重建；相对时间不得作模型通道 |
| 运动测量 | 9 | `x/y/z`、`rotationRateX/Y/Z`、`gravityX/Y/Z` | 经第二层适配后训练；绝对重力为条件训练 |
| 触摸位置快照 | 2 | `x_norm/y_norm` | 采集时最近位置的轻量派生；正式触摸对齐以 `touchFrames[]` 为准 |
| 双时钟 | 2 | `sensorTimestampElapsedRealtimeNanos`、`receivedElapsedRealtimeNanos` | 插值和因果门；禁止作通道 |
| 来源控制 | 3 | `sensorSource`、`streamEpoch`、`trainingInput` | 判断流切换和训练资格；不得作为数值通道 |
| 合计 | 20 |  |  |

`delta` 虽存在于内存计算对象中，但不写入 `frames[]`；`maxAbsDelta` 也不是逐帧落盘通道。需要冲击变化量时，应在派生层按统一时间网格重算，不能依赖旧的临时值。

### 3.4 `touchFrames[]`：逐触摸事件数据

`touchFrames[]` 保存事件序列，不是整次触摸的结束汇总。

| 数据组 | 字段 | 当前用途 | 跨设备注意事项 |
| --- | --- | --- | --- |
| 索引与相对时间 | `frameIndex`、`relativeTimestamp` | 顺序和审计 | 不作模型通道 |
| 触摸双时钟 | `eventTimeMillis`、`eventElapsedRealtimeNanos`、`receivedElapsedRealtimeNanos` | 与 IMU 对齐和因果门 | 必须使用单调时钟语义 |
| 视图几何 | `viewWidthPx`、`viewHeightPx` | 坐标和接触轴归一化依据 | 坐标单位和接触轴单位必须分开声明 |
| 原始位置 | `x/y` | 可重建位置 | Android 像素与 iOS point 不可直接比较 |
| 即时归一化位置 | `x_norm/y_norm` | 第二层的输入证据 | 仍需处理屏幕旋转 |
| 接触测量 | `pressure`、`size`、`touchMajor`、`touchMinor` | 条件训练 | OEM 量程、语义、DPI 和覆盖率不同 |
| 工具测量 | `toolMajor`、`toolMinor`、`toolType` | 仅观察 | 不能代替真实触摸接触长短轴 |
| 方向 | `orientation` | 原始保留 | 零方向和缺失语义不稳定，当前正式触摸模型移除 |
| 指针与动作 | `pointerCount`、`pointerId`、`actionMasked`、`actionIndex` | 单指筛选和事件审计 | 平台枚举需适配 |
| 元数据版本 | `metadataEpoch` | 定位逐帧 View/输入设备元数据切换 | 正整数、单调不回退；根级版本必须等于首帧 |
| 可用性 | `axisAvailability`、可选 `inputDeviceMetadata` | 区分缺失和真实 0 | availability 可能暴露设备身份 |
| 单帧派生 | 单帧 `contactPatch` | 观察和复算对照 | 当前不在正式 v2 白名单 |

`touchMetadata.metadataEpoch` 表示首个触摸帧所属版本，每个 `touchFrames[].metadataEpoch` 表示该帧版本。日志器以记录级显示快照、逐帧 `viewWidthPx/viewHeightPx` 和逐帧 `inputDeviceMetadata` 生成指纹：相邻指纹不变则 epoch 不变，变化则递增，且跨样本不回退。审计拒绝缺失/非正整数、根级与首帧不一致或逐帧回退。当前触摸帧没有保存事件发生瞬间的 `displayRotation/windowInsets`，所以只能定位已有逐帧 View 和输入设备证据的变化，不能倒推出触摸内部未记录的旋转或 Insets 历史。

### 3.5 姿态观察流

采集器按下列顺序尝试姿态源：

```text
TYPE_GAME_ROTATION_VECTOR
  -> TYPE_ROTATION_VECTOR
  -> TYPE_GEOMAGNETIC_ROTATION_VECTOR
  -> unavailable
```

对应 `rotationFrames[]` 保存来源、硬件时间、接收时间、精度、数值和 `streamEpoch`。这些数据当前 `trainingInput=false`，仅用于观察姿态、验证参考系和未来消融，不直接进入 CNN。

### 3.6 采集时实时处理

1. 加速度优先采用 `TYPE_LINEAR_ACCELERATION`。
2. 回退到普通加速度计时，只有重力流健康且时间差不超过 50ms，才计算 `linearAcceleration = accelerometer - gravity`。
3. 缺少可信重力时保留原始加速度作为证据，并标记 `trainingInput=false`，不得静默进入训练。
4. `x_norm=x/viewWidth`、`y_norm=y/viewHeight`，并截断到 `[0,1]`。
5. Android 传感器值保留在设备机身轴中，通过元数据声明单位、来源和轴；采集层不转到地球参考系。
6. 采集层不做固定九槽重采样、robust scaler、session baseline 或训练集统计归一化。

因此，采集层输出既有原始数据，也有 `x_norm/y_norm`、来源资格等轻量派生数据；但没有可直接送入最终模型的完整规范矩阵。

### 3.7 触摸结束时处理

采集结束后保留可变长度双锚点原始窗口：

```text
起点：down-85ms 与 down 前第 15 个真实 IMU 帧中更早者
终点：lift+85ms 与 lift 后第 15 个真实 IMU 帧中更晚者
```

前后两侧必须分别同时满足至少 85ms 和 15 个真实帧，才可标记完整。该窗口用于保留冗余，不等于训练窗口。

结束时还会生成根级 `contactPatch`、`contactEncoding`、`touchNormalization`、能力摘要和历史预测。这些对象可能读取决策时刻后的触摸帧，按下期模型一律不得使用。

## 4. 第二层：逐时间戳归一化数据

### 4.1 本层目的

把不同设备的可变频率事件流变成相同物理时间、单位、机身参考系、屏幕方向和缺失语义下的固定矩阵。

### 4.2 固定物理时间网格

1. `ACTION_DOWN` 事件硬件对齐时间定义为 `0ms`。
2. 固定九槽为 `[-15,-10,-5,0,5,10,15,20,25]ms`。
3. IMU 连续量按 `sensorTimestampElapsedRealtimeNanos` 线性插值。
4. 每槽必须存在左右真实支撑帧；最大间隔为 `max(10ms, 4 × 窗口内中位采样间隔)`。
5. 不按数组索引推时，不外推，不用名义采样率制造伪帧。
6. 抬起早于 `+25ms` 时拒绝当前按下期窗口。

### 4.3 IMU 单位与参考系统一

统一目标是 canonical device 机身参考系：

```text
x = device_right
y = device_up
z = device_outward
```

| 数据 | 统一规则 | 当前风险 |
| --- | --- | --- |
| 线性加速度 | 统一为 `m/s²`；含重力来源必须先减同时间轴重力 | Android/iOS 来源名和滤波实现不同 |
| 陀螺仪 | 统一为 `rad/s` | 轴符号、轴顺序和单位声明可能不同 |
| 重力 | 使用显式正交矩阵转到 canonical device，不转到地球参考系 | 绝对重力会编码握持姿态 |
| 轴变换 | 读取版本化 `axisTransformMatrix`；矩阵必须正交且行列式绝对值为 1 | 禁止根据样本数值猜平台轴 |

需要分别比较三种重力视图：保留绝对重力、删除重力、使用相邻时间槽的 `delta gravity`。绝对重力不是默认可靠的跨姿态特征。

### 4.4 触摸时间对齐和归一化

触摸频率通常低于 IMU。每个目标 IMU 时间槽使用零阶保持（ZOH），只选择同时满足以下条件的最后一个 `touchFrame`：

```text
touch.eventElapsedRealtimeNanos <= target IMU sensor time
touch.receivedElapsedRealtimeNanos <= target IMU availability time
```

触摸归一化规则：

| 通道 | 处理 | 限制 |
| --- | --- | --- |
| `x/y` | 除以 View 宽高，再按屏幕方向变换到标准方向 | 刘海、安全区和实际交互区域仍可能不同 |
| `touchMajor/touchMinor` | 当前除以 View 对角线，生成 `major_norm/minor_norm` | 只统一相对屏幕比例，不保证毫米物理等价 |
| 长短轴比例 | 生成 `log_axis_ratio` | 任一轴缺失时必须由 mask 标记 |
| `pressure/size` | 截断到 `[0,1]`，原值仍在原始 JSON 保留 | 不是跨 OEM 统一物理压力或面积 |
| `orientation` | 派生 `sin/cos` | 仅作为中间结构，当前正式触摸模型删除 |
| 缺失值 | 数值位置写 0，同时保留独立 availability | 0 不能被解释为真实小值 |

坐标量纲和接触轴量纲必须分别声明。不能因为视图尺寸字段名带 `Px`，就默认 `touchMajor/touchMinor` 在所有设备和平台都与坐标使用相同单位。

### 4.5 本层输出

| 合同 | 形状 | 通道组成 |
| --- | ---: | --- |
| `causal_time_grid_imu11_v2` | `9×11` | 坐标 2 + 线性加速度 3 + 陀螺仪 3 + 重力 3 |
| `causal_time_grid_imu11_touch9_v2` | `9×20` | 上述 11 + pressure、size、major、minor、轴比、方向正余弦、指针数、touch_valid |

同时输出 `missingMasks`、`gridQuality`、`sourceSha256`、来源 manifest 和拒绝原因。原始 JSON 只读，不在本层覆盖。

## 5. 第三层：训练端使用的清洗后数据

### 5.1 清洗与污染控制

| 操作 | 规则 | 防止的问题 |
| --- | --- | --- |
| 来源一一对应 | accepted source、11 通道矩阵、20 通道矩阵按 SHA-256 对齐 | 错配和重复来源 |
| 形状与有限值检查 | 九槽、通道数、有限值、0/1 mask 必须满足合同 | 损坏样本 |
| 标签检查 | 只允许四个目标类别 | 未知标签污染 |
| 单指筛选 | 当前任务排除多指样本 | 任务定义漂移 |
| 来源资格 | 原始加速度无可信重力、流 epoch 混乱或元数据不足时拒绝 | 物理语义不一致 |
| 精确重复降权 | 同 group、同类、完全相同矩阵按重复数降权 | 重复回调放大贡献 |
| 分组切分 | `groupId=platform+deviceId+sessionId`，整组只进训练或验证一侧 | session 和设备泄露 |

禁止作为模型通道的数据包括：原始时间戳、相对时间、collector、session、deviceId、设备型号、文件名时间、人工标签文本/编号、抬起时间、整次触摸汇总和历史模型预测。

### 5.2 清洗矩阵和实际训练视图

| 名称 | 形状 | 定义 | 合同/状态 |
| --- | ---: | --- | --- |
| `imu11` | `9×11` | 第二层 IMU 规范矩阵 | `causal_time_grid_imu11_v2` |
| `touch20` | `9×20` | 第二层 IMU + 触摸中间矩阵 | `causal_time_grid_imu11_touch9_v2` |
| `touch26` | `9×26` | `touch20` + 6 个 availability | `causal_time_grid_imu11_touch9_mask6_v3`，清洗中间结构 |
| `touch23` | `9×23` | 从 `touch26` 删除方向 sin、方向 cos、方向 availability | `causal_time_grid_imu11_touch7_mask5_v3`，当前完整触摸训练视图 |
| `no_gravity` | `9×20` | 从 `touch23` 删除绝对重力三轴 | `causal_time_grid_touch7_mask5_no_gravity_v1`，实验模型 |
| `delta_gravity` | `9×23` | 用相邻槽重力差替换绝对重力，第一槽置 0 | `causal_time_grid_imu11_touch7_mask5_delta_gravity_v1`，实验模型 |

`touch23` 的 23 个通道为：

| 通道组 | 数量 | 字段 |
| --- | ---: | --- |
| 位置 | 2 | `x_norm`、`y_norm` |
| 线性加速度 | 3 | `userAcceleration.x/y/z` |
| 陀螺仪 | 3 | `rotationRate.x/y/z` |
| 重力或重力差分 | 3 | `gravity.x/y/z` 或对应差分 |
| 触摸测量 | 5 | `pressure`、`size`、`major_norm`、`minor_norm`、`log_axis_ratio` |
| 触摸状态 | 2 | `pointer_count`、`touch_valid` |
| 可用性 | 5 | pressure、size、major、minor、pointer count availability |
| 合计 | 23 |  |

availability 是必要的缺失语义，但也可能间接编码设备能力。必须通过未见设备留出验证其收益，不能仅凭同设备验证决定保留。

### 5.3 统计标准化

1. 严格评估时，scaler 只能在训练分区拟合。
2. 连续通道使用中位数和四分位距的 robust scaling，并截断到 `[-8,8]`。
3. `x_norm/y_norm`、`touch_valid` 和 availability 使用 identity。
4. 不可用的触摸测量不参与对应通道 scaler 拟合；变换后由 mask 控制为 0。
5. 验证集、session、collector 和设备身份不得影响 scaler。

### 5.4 当前 CNN 训练配置

| 参数 | 当前值 |
| --- | --- |
| 网络 | 两层 Conv1d，32 通道，kernel 3；GroupNorm 4；GELU；Dropout 0.15；时间均值池化；四分类线性层 |
| 优化器 | AdamW |
| 初始/最低学习率 | `0.001` / `0.00001` |
| 调度器 | CosineAnnealingLR |
| 权重衰减 | `0.001` |
| 批大小 | `64` |
| 最大轮数 | `80` |
| 早停耐心 | `12` 轮，仅严格验证训练适用 |
| 梯度裁剪 | L2 norm `1.0` |
| 随机种子 | `20260810` |

严格评估必须按 `platform+deviceId+sessionId` 分组留出，并报告跨 session/设备泛化。全量训练可以使用全部 eligible 数据拟合 scaler 和权重，但没有独立验证集，只能用于装机兼容性与受控 A/B，不能证明泛化能力或替代严格评估。

## 6. 第四层：运行端模型装机输入数据

### 6.1 在线执行顺序

1. App 持续维护 IMU 和触摸滚动缓存。
2. `ACTION_DOWN` 建立 `0ms`，并保留按下前缓存。
3. 每个回调只更新缓存，不立即调用 CNN。
4. 等待硬件时间覆盖 `+25ms`，并获得该槽右侧真实 IMU 插值支撑。
5. 按模型 `featureContract` 在线复现第二层的单位转换、显式轴变换、九槽插值、触摸 ZOH、几何归一化和缺失 mask。
6. 使用模型随附的固定 scaler 复现第三层转换。
7. 一次性将完整 `9×通道数` 矩阵送入 CNN，输出四类概率、类别、置信度和 `modelId`。

运行端等待的是完整物理时间窗口，不是等待抬起。实际延迟约为 `+25ms` 加上传感器回调和右支撑到达时间。

### 6.2 运行端拒绝条件

- 模型合同、通道顺序、矩阵形状、网格、scaler 或权重哈希不一致。
- 任一必需槽缺少左右真实支撑，或采样间隔超过合同上限。
- 触摸事件时间或接收时间缺失，无法证明因果可用性。
- 抬起发生在 `+25ms` 之前。
- 加速度来源不可训练、单位/轴元数据缺失或流 epoch 不一致。
- 条件触摸字段缺失但模型合同没有对应 availability 处理。

运行端不得读取根级 `contactPatch`、`contactEncoding`、`touchNormalization`、抬起后数据、身份字段、人工标签或原始时间戳作为模型数值通道。

### 6.3 当前模型状态

当前默认模型仍为：

```text
oneplus_four_class_after_recollect_hard_nearfull_weighted_old13_multichannel
```

以下时间网格模型仍是全量拟合实验模型，不是已通过跨设备严格验证的正式模型：

```text
time_grid_all_data_touch23_experimental
time_grid_all_data_no_gravity_experimental
time_grid_all_data_delta_gravity_experimental
```

它们必须保留 `all_data_fit_only` 或等价标记，并设置 `deploymentAllowed=false`；可用于受控真机比较，不得据此宣称跨设备效果已达标。

## 7. 跨设备风险总表

| 风险对象 | 可能差异 | 当前控制 | 仍需验证 |
| --- | --- | --- | --- |
| IMU 采样率 | 设备、功耗策略、ROM 限频不同 | 按硬件时间九槽插值 | 不规则采样和高负载下拒绝率 |
| 加速度来源 | 线性加速度、普通加速度、厂商滤波不同 | 来源标签、重力健康门、不可训练回退 | Android/iOS 等价性 |
| 陀螺仪 | 单位、轴符号、零偏不同 | 单位转换和显式正交矩阵 | 未见设备零偏和温漂 |
| 绝对重力 | 强烈编码屏幕朝向和握持姿态 | absolute/no-gravity/delta-gravity 对照 | 姿态留出召回率 |
| 触摸坐标 | pixels、points、旋转、安全区不同 | View 归一化和屏幕方向变换 | 可交互区域定义 |
| 接触长短轴 | 单位、DPI、触控固件、缺失不同 | 对角线归一化和 mask | 是否需要毫米校准或删除 |
| pressure/size | OEM 量程和语义不同 | 原值保留、`[0,1]` 截断、mask | 跨设备可比性和消融收益 |
| orientation | 零方向、范围、覆盖率不同 | 原始保留，正式 touch23 删除 | 未来统一方向合同 |
| 工具轴 | 支持率和语义不稳定 | 只观察 | 不得代替接触轴 |
| availability | 设备能力集合不同 | 显式缺失语义 | 是否成为设备身份捷径 |
| 元数据 epoch | 触摸内可能变化 | 根级首帧版本 + 逐帧单调版本；View/输入设备变化递增 | 事件级旋转/Insets 尚未采集 |
| session/采集者 | 可能与标签绑定 | 分组切分和禁止作特征 | 多设备、交错标签采集 |
| 整次汇总 | 含决策时刻后的信息 | 明确禁止进入按下期模型 | 静态审计和回归测试 |

## 8. 当前未完成事项

1. iOS 仍需补齐并真机验证与 Android 同等级的 schema v6 双时钟、单位、轴变换、触摸字段可用性和原始冗余窗口合同。
2. `touchMajor/touchMinor` 的物理量纲尚未跨 OEM 和跨平台证明等价；View 对角线归一化只能统一相对屏幕比例。
3. `pressure/size` 不是统一物理量，必须完成未见设备分布审计和通道消融。
4. `metadataEpoch` 已覆盖逐帧 View 尺寸和输入设备元数据变化，但 `displayRotation/windowInsets` 仍只有记录级快照；折叠屏、多窗口或旋转在单次触摸内部发生时，尚不能按事件时间精确定位。
5. availability 可能泄露设备能力；绝对重力可能泄露握持姿态，两者都需跨设备严格留出。
6. 当前三个时间网格全量模型没有独立验证集，不能替代分组验证。
7. 最近 7 条旧实现真机样本的采集合同审计为 4 条通过、3 条失败；原因是能力分析器曾跨触摸累计，使后续退化样本可能继承先前的 `touchAxesDistinct=true`。当前代码已改为按本次 `activeTouchFrames` 重建单条记录画像，但这 7 条历史文件不会被追溯改写，仍不得作为新合同已验收的证据；必须使用修复后的 APK 重新采样并审计。

## 9. 验收标准

### 9.1 采集层

- schema v6 每个 `frames[]` 元素具备上述 20 个落盘字段和有效双时钟。
- 每个 `touchFrame` 具备事件时间、接收时间、视图尺寸、字段可用性、输入来源证据和正整数 `metadataEpoch`；epoch 单调不回退，根级值等于首帧。
- 完整样本的按下前、抬起后覆盖各自同时不少于 85ms 和 15 个真实 IMU 帧。
- 采集能力判定按触摸隔离，不继承上一条样本状态。

### 9.2 时间归一化层

- 同一物理信号在 120Hz、200Hz、240Hz 和不规则采样下生成误差范围内一致的九槽矩阵。
- Android 与 iOS 经单位和显式轴变换后落入同一 canonical device 参考系。
- 修改 `+25ms` 之后的数据、抬起后汇总或身份字段，不改变九槽模型输入。
- 不完整支撑、时间回退、流切换和不可训练加速度均产生明确拒绝原因。

### 9.3 清洗训练层

- 原始来源与全部矩阵按 SHA-256 一一对应，无跨标签重复和错配。
- 同一 `platform+deviceId+sessionId` 不跨训练集与验证集。
- scaler 仅由训练分区拟合，验证集和身份字段不参与任何特征变换。
- 报告包含 balanced accuracy、macro F1、四类召回、最差 session、最差设备、拒绝率和实际等待延迟。

### 9.4 运行层

- Python 与 Android 对同一原始样本生成的输入矩阵逐元素一致。
- 模型合同、通道顺序、九槽偏移、mask、scaler 和权重哈希均可校验。
- 在线只在 `+25ms` 及右支撑到达后调用一次 CNN；不依赖抬起事件。
- 所有缺失或合同不匹配场景拒绝推理，不静默补伪数据。
